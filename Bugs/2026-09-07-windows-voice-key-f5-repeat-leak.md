# 2026-09-07 Windows 版语音键原生 F5 泄漏（key-repeat 突破 180ms 抑制窗口）

- 功能点：Windows 版语音键抑制器（遥控器物理语音键产生的原生 F5 系统事件）。
- 触发条件：按住/点按遥控器语音键时，焦点在浏览器（如 DSH 网页）的窗口收到 F5 → 页面刷新。

## 复现证据

- F13 注入修复（commit `4b82316`）已生效并重启后，用户现场反馈"按一下语音键还是会刷新页面"——注入键 F13 浏览器无响应，刷新只能来自原生 F5 事件泄漏。
- 代码复核（`KeyboardEventSuppressor.ShouldSuppress`）：`Arm(down)` 记录 180ms 窗口后，首个原生 F5 down 被吞并立即 `_armingTimes.Remove(vk)`；此后同一按住期间系统自动生成的 key-repeat F5 down（按下约 500ms 后开始连续重复）以及蓝牙延迟超过 180ms 的首个 down，全部落空抑制 → 泄漏到前台应用。

## 根因

抑制器对语音键沿用"单发按键 180ms 边沿窗口"语义，而语音键是会话型按键（按住数秒）。按住期间的原生 F5 重复事件无法被单发窗口覆盖。

## 修复

- `KeyboardEventSuppressor` 新增会话级抑制（sticky）：`Arm(vk, down, sticky: true)` 起持续吞掉该 VK 的非注入 down/up（含 key-repeat），直到 `Arm(vk, up)`；带 65 秒超时保护——若释放事件因蓝牙断连丢失，超时后自动放行避免永久吞键。
- 仅语音键（HID usage 0x3E → VK_F5）使用 sticky 语义；其他按键保持 180ms 单发窗口不变。
- 语音键注入键保持 F13（浏览器无响应），新增 `ctrl_win_hold` 语音键模式（按住注入 Ctrl+Win）适配微信输入法"按住说话"快捷键。

## 验证

- 构建 0 错误，程序重启 BLE READY。
- 用户实测边界：按住语音键不再刷新浏览器、微信输入法模式文字上屏——待用户在真机确认；本记录先按代码级验证归档，真机结论以用户反馈为准。
